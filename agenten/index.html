Wie KI-Agenten
arbeiten

Ein Sprachmodell kann nur Text schreiben. Ein Agent kann damit handeln: Dateien lesen, Tests ausführen, Tickets anlegen. Dahinter steckt keine Magie, sondern eine einfache Schleife und ein paar Werkzeuge. Hier siehst du, wie sie zusammenspielen und wo es gefährlich wird.

01 · Grundlagen

Die Schleife

Im letzten Teil hast du gesehen: Ein Sprachmodell schreibt Wort für Wort eine Fortsetzung. Ein Agent nutzt genau das, aber in einer Schleife. Das Programm drumherum gibt dem Modell eine Aufgabe und fragt immer wieder: Was ist der nächste Schritt?

  1. Denken: Das Modell schreibt auf, was es als Nächstes vorhat.
  2. Handeln: Es ruft ein Werkzeug auf, zum Beispiel „Tests ausführen“.
  3. Beobachten: Das Ergebnis wird an den Text angehängt, und die Runde beginnt von vorn.

Das geht so lange, bis das Modell meint, fertig zu sein. Achte auf den Balken unter dem Verlauf: Alles, was passiert, landet im Kontext. Das Modell hat kein anderes Gedächtnis.

MerkeEin Agent ist ein Sprachmodell in einer Schleife: denken, ein Werkzeug benutzen, das Ergebnis lesen und wieder von vorn.

Geh Schritt für Schritt durch, wie ein Agent einen kaputten Test repariert.

    Werkzeuge

    Ein Modell weiß nur, was es beim Training gelesen hat. Es kennt das Wetter von morgen nicht, sieht keine Tickets und rechnet große Zahlen im Kopf eher schlecht. Ohne Werkzeuge bleibt ihm nur: raten.

    Darum bekommt ein Agent eine Liste von Werkzeugen, jeweils mit Name, Beschreibung und den Werten, die es braucht. Das Modell führt dabei nichts selbst aus. Es schreibt nur einen strukturierten Wunsch auf, etwa rechner("48271 * 3907"). Das Programm drumherum führt ihn aus und hängt das Ergebnis an den Text.

    Schalte die Werkzeuge an und aus und vergleiche die Antworten.

    MerkeWerkzeuge geben einem Modell Zugriff auf aktuelle Daten und echte Aktionen. Das Modell entscheidet, welches es braucht, ausgeführt wird es vom Programm.

    Woher weiß das Modell, wofür ein Werkzeug gut ist?

				03 · Model Context Protocol
				
      Ein Stecker für alles
      
				
      Jede KI-Anwendung will an viele Systeme: Code, Tickets, Kalender, Datenbanken. Früher musste jede
					Anwendung für jedes System einen eigenen Adapter bauen. Bei 5 Anwendungen und 8 Systemen sind das 40
					Adapter, und jeder geht anders kaputt.
      
				
      Das Model Context Protocol, kurz MCP, ist ein offener Standard, der 2024 vorgestellt
					wurde. Ein System bietet seine Werkzeuge über einen MCP-Server an, eine KI-Anwendung
					spricht sie über einen MCP-Client an. Jede Seite muss das Protokoll nur einmal können.
				
      
				
      Das ist dieselbe Idee wie bei USB: Früher hatte jedes Gerät seinen eigenen Stecker, heute passt fast
					alles in dieselbe Buchse.
      
				
      MerkeMCP ist ein gemeinsamer Stecker zwischen KI-Anwendungen und Werkzeugen.
					Statt Anwendungen mal Systeme braucht es nur noch Anwendungen plus Systeme.
      
				
      
					Mehr Werkzeuge, mehr Verantwortung
					
      Ein MCP-Server gibt einem Agenten Hände. Deshalb lohnt es sich zu prüfen, welche Server man
						anschließt, was sie dürfen und mit wessen Rechten sie arbeiten.
      
				
      
			
      
			
      
				
      Verändere die Zahl der Anwendungen und Systeme und schalte dann MCP ein.

				04 · Sicherheit
				
      Wenn Text zum Befehl wird
      
				
      Für ein Sprachmodell ist alles Text im selben Kontext: deine Aufgabe, das Ergebnis eines Werkzeugs,
					der Inhalt einer E-Mail. Es kann nicht zuverlässig unterscheiden, was eine Anweisung von dir ist und
					was nur Daten sind. Wer also Text in den Kontext schmuggelt, kann dem Agenten Befehle geben. Das heißt
					Prompt Injection.
      
				
      Gefährlich wird es, wenn drei Dinge zusammenkommen. Der Entwickler Simon Willison nennt sie die
					tödliche Dreierkombination: Der Agent hat Zugriff auf private Daten,
					liest fremde Inhalte und kann nach außen senden. Fehlt eines davon,
					läuft der Angriff ins Leere.
      
				
      Unten bittest du einen Assistenten, deine E-Mails zusammenzufassen. In einer davon steht unsichtbarer
					Text. Probier aus, welche Einstellungen den Angriff stoppen.
      
				
      MerkeEin Agent kann Daten nicht sicher von Befehlen unterscheiden. Schutz
					entsteht durch Grenzen: wenige Rechte, keine Dreierkombination und ein Mensch, der wichtige Aktionen
					bestätigt.
      
			
      
			
      
				
      Stell die Rechte des Agenten ein und starte ihn. Versuch, den Angriff auf mehreren Wegen zu
					stoppen.
